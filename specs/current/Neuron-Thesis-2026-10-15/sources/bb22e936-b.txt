# Neuron / Cortex V16 — Graph-Is-Math Architecture

## 1. The mistake in V15.x

V15.x was still built around the assumption that Cortex contained a graph **and then some runtime had to reason over that graph**.

That is the wrong abstraction.

We kept putting intelligence outside the organism:

- Python interpreted relationship types.
- Python searched for candidates.
- Python decided how composition worked.
- Python performed semantic reasoning.
- formulas were treated as instructions to execute.
- graph edges were treated as stored semantic facts.
- words or semantic labels were allowed to become structural identities.
- learning and using knowledge were partially conflated.

That made Cortex look as though it needed a graph database plus a reasoning engine.

V16 should reject that model.

The graph is not data being reasoned over.

> **The mathematical shape of the graph is the learned reasoning itself.**

The expensive computation happens while learning the shape.

After learning, ordinary use should mostly be activation and traversal of already-materialized topology.

---

# 2. Core V16 assertion

A Cortex gate/neuron occupies exactly one canonical mathematical-expression identity.

For example:

\[
E_a=x
\]

\[
E_b=-x
\]

\[
E_c=\frac{1}{x}
\]

\[
E_d=\sin(x)
\]

These expressions are not numbers being calculated during ordinary cognition.

They are **addresses / structural identities / code**.

The expression *is the location.

The relationship between two gates is represented by a learned mathematical transform that maps one canonical expression to the other.

If:

\[
E_b=F(E_a)
\]

then once Cortex has learned and materialized that relationship, a later run should not have to rediscover why \(E_b\) follows \(E_a\).

The graph already embodies that fact.

> **Learning computes. Running traverses.**

Learning is where Cortex must discover:

1. that two experienced states are related;
2. whether that relationship matches an existing mathematical transform;
3. or whether a new transform is required;
4. where the resulting canonical expression belongs;
5. whether that location already exists;
6. whether independent routes agree;
7. what provenance supports the placement;
8. what existing topology must now be back-populated.

This can be mathematically expensive.

The hypothesis is specifically:

> **pay heavily once while learning so that future cognition is almost entirely topology traversal.**

# 9. Pattern discovery emerges from topology

As the graph becomes dense, relationship discovery stops being an unconstrained search over mathematics.

New evidence arrives into an already highly constrained structure.

> Which of the three already-predicted holes matches this observation?

That is a radically smaller problem.

# 17. V16 learning pipeline

Do not start with English semantic rules.

A learning event should approximately be:

### 1. Observe form/context

Encoder captures raw observable structure.

### 2. Resolve already-known gates

Known portions activate existing canonical expressions.

### 3. Identify unknown

A form, relation, or destination cannot yet be resolved.

### 4. Generate mathematical constraints

Existing topology supplies constraints on where the unknown could live.

### 5. Search relationship mathematics

Only now may expensive learning compute/search occur.

Search for the lowest-complexity mathematical relationship consistent with observations and already-known topology.

### 6. Validate against independent examples

Do not accept a relationship because it explains one pair.

Require it to predict additional existing structure or withheld examples.

### 7. Canonicalize destination

Resolve the resulting expression to the appropriate canonical normal form.

### 8. Materialize gate if absent

If the canonical gate does not exist, create it.

### 9. Materialize relationship DNA

Persist the learned formula/topology.
