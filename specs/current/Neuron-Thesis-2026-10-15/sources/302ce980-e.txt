# STEPBACK-NS-014: what the brain stores and what graph code can read (2026-10-02, Claude)

Read-only map. Queries ran on a copy (/tmp/claude-1000/stepback-map/copy.db). The rail and the live brain were not touched.

## The data is there
Every run's route is stored step by step.
- `occurrence.cells.route` is the ordered list of route rows (physics.py:500).
- Each route row is `dna` kind='route' with these columns:
  - gate_id
  - arrival_gate = the receipt of the completed prefix
  - key_gate
  - dest_gate
  - out_gate = the next arrival
  - via = the shard id
  - shape j/f/l
- Rows are written by physics._step (:91-110) through substrate.add_route (:417).

The owner's "DNAs that arrived at that gate exactly the same" is exactly `dna WHERE kind='route' AND gate_id=? AND arrival_gate=? AND until_event IS NULL`. The index `dna_route` already serves that lookup.

Example: 'summer opposite ?' (event 15001)
- route rows 101289 → 101393 (via shard 101392: summer -opposite-> winter) → 101452
- memory neuron 11491 (keys summer, opposite, ?)
- occurrence 344521, outcome ANSWERED, out [winter]
- At (summer, arrival [summer]) there are 10 sibling route rows. One is `?` → [summer ?], with 5 occurrences: the first ANSWERED, the next 4 UNRESOLVED.

Facts a step-back must respect:
- A shard is chosen by (gate, key). The arrival chooses the cached route row, which names the shard.
- Actions, stored-run steps and `--run` programs lay no route rows.
- Outcome is per occurrence. Lessons and corrections create occurrences too (check event.meta.why).
- Shards never taken from an arrival have no route row and no known outcome.
- At ROOT the sibling set is 2,858 rows. Stepping back to ROOT is a big search, which the owner forbids (72). Stop one node short of it.

## What graph code cannot do today
- No opcode reads route, occurrence or mail rows. QUERY's descriptors are graph data
