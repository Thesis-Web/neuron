**One correction to how the line is drawn.** Inside SQLite everything is SQL, including a neuron firing, because a trigger runs SQL. So the real split isn't "SQL versus neurons." It's this:
- **SQL the physics is born with.** These are hand-laid triggers whose statements are fixed. Firing them never leaves the database.
- **SQL the brain writes.** This is a string put together from neurons. Plain SQLite can't run a string: calling eval without the extension fails with "no such function: eval", and a trigger can't create another trigger (that's a syntax error).

So running code the brain wrote needs one jump out, the eval function. That's your mother, and it's env. Whatever opens the brain has to load it, and has to switch on `recursive_triggers`, every time.

**Which of your slashes can be neuron runs without jumping out: all of the writing.** Each token neuron fires, adds its word, and hops to the next. The gates, shards and memories of that run can all be fixed physics, with no eval. The only jump out is at the end, when /build hands the finished text to eval.

1. Every token is a hand-laid neuron.
