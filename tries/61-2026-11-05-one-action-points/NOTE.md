## Prefixes and suffixes (affix_read.py, affix-read-live.txt, affix-nodes-live.txt)

## The owner's check (05:1x): is the action C outside the brain?
The prose: reference draft 10-23 line 265, "The brain writes its own SQL and hands it to mother, and she drops it at the SQL prompt"; the owner 10-22 23:29, "runs in the neurons that outputs to a mother that just takes the output and writes it to the sql prompt then returns the output as a sub input to the brain". The traced shape matches it: the called run carries the SQL words, the closing BUILD hands the text to mother, mother pastes it at the SQL prompt (sqlite3_exec), the answer returns as a run under the run that asked. The storage under the prompt is the kernel's virtual tables (the hub: SQLite's own file), the engine reading bytes. Where it departs, all mine and in C: the SQL text itself (my line files; the brain stores and replays it); decode_span edits the text before mother pastes it; the dedupe skips the landings on the SQL-word neurons when a run repeats, so their rows never get a turn; a dna read by the full key lays the shard. What the brain can change from inside: rebind a call (UPDATE dna SET call), write a new run (INSERT INTO input, or seq appended in order; a run's symbols cannot be edited in place: seq_update appends only). Live: select, from, where are born and defined, each with one row, the birth's define spawn, never hit; dna, gate, =, what hold no rows; the uppercase SQL gates in the old lines are born 0.
