# DECISIONS (turn one, hp2)

One line per decision the documents leave open.

- Setup: `neuron` is a system user (nologin, no sudo, no ssh keys); james is in group `neuron` so the sockets (0660, group neuron) can be reached; neuron gets `x` on /home/james by ACL and read on `neuron-build/` only.
- SQLite driver: github.com/mattn/go-sqlite3 v1.14.24 (cgo; gcc is on hp2). It is the only Go dependency.
- Absent is no row: optional fields live in their own tables (phys, val, proc, msig, mbody, mout); no NULL columns, no blank stand-ins.
- The pad is a stack; physics words pop by kind (most recent gate / number / point / text / any). A one-element list stands for its element.
- READ and WRITE also reach the run's own pad and slots (`LAST`, `SLOT`, `MODE`, `ITEM`), and DELETE reaches `LAST`: the scratch pad counts as rows of the run, not a new physics word.
- Arrival inside a process string is the process (the frame). The doc's "how a run arrives" holds for input words (arrival = the previous gate); inside processes it keeps branches from colliding on shared physics gates.
- A branch is a jump: when an outcome is taken, the rest of the test's frame is skipped. GO is also a jump. An empty process (`carry-on`) is the "just continue" branch.
- `on P OUTCOME -> T` attaches to the last physics word in P.
- Tests: READ and FIND put NONE at the head only when absent (found = no outcome, fall through); COMPARE always puts SAME/MORE/LESS; READ KIND puts GATE/NUMBER/TEXT/POINT/LIST; READ GROUNDED puts YES/NO/NONE.
- The miss is a hardware-style interrupt: the kernel keeps the miss (MAT, MFROM, MHEAD) on the run and GOes to the gate's miss process with arrival = the miss gate. Three nested misses end the run as a fault.
- The watchdog: a run past STUCK steps is sent once to the `stuck` process (the "am I stuck?" question needs a step count only the kernel sees).
- Kernel-started runs (input, split, sixth, end-of-run, miss) start at their gate with arrival = that gate. Input runs start at the HEAR gate.
- The loader lays the shards each told string steps through (a static walk of the string, including its calls and branches). They are told rows. Input words lay their shards through the miss way at first use.
- Triggers fire only on hops of input items (depth 0), not on process internals; otherwise every process step would start question storms. Question runs that HEAR text are input-level again, so they ask their own questions (blueprint §11.2 step 4).
- A new shard copies its gate's usual triggers when it is written (in WRITE SHARD), as §7.3 says.
- Shard counts are rough buckets (1, 2, 3 = once, a few, a lot); only a change of bucket writes, so a hop that is "done a lot" writes nothing.
- A run's memory row exists from its first write, so receipts written mid-run point at a real memory. A run that wrote nothing and matches a signature touches that row (same row, new time).
- Signature = the gates the run hopped to from input (depth 0). Shape = the direction of each move between those gates' points, in 27 ways, as an index key.
- A memory written at the end of a run puts a receipt (its id) in the Use section of each of its input gates, once, when the memory is new.
- The decoder says `en` labels first, then key labels. A number is said as its digits (a value, like a display, not a word). Everything a beat says to one person goes out as one line.
- A label written later is reached first (a person naming a gate wins over the key it typed).
- Encoder: split at spaces and at every non-letter/non-digit key; exact label first, then lowercase (shift is a key, not a different letter).
- SAY, CALL and WRITE PROC are refused by the kernel unless the run passed `core-ok` since its last such act; `core-ok` is reached only through the core-check processes, which are core rows the kernel won't let anything write.
- Core values as actions: don't lie = a guessing run says `maybe` first; don't cheat = NONE is never said or written as an answer; stay home = CALL only through a listed source; do no harm = ungrounded ports (programs, friends) only by the brain's own choice (mode DERIVED), never because someone told it; never take an LLM's word as truth = a run that reads an ungrounded source writes in GUESS mode.
- Told gates without relationships get distinct points on a unit sphere (a Fibonacci spiral by gate number) until relationships pull them, so they aren't all "two meanings at one point" at the origin. Newborns spawn at the origin, as §5.5 says.
- Relationship formulas (first guesses): same = identity, opposite = negation, contradicts = negation, kind-of = ×0.9, part-of = ×1.1, like/describes/supports = +0.1y, cause = +0.1z, before/derived-from = −0.1z, used-for = +0.1x. Inversion (p/|p|²) is laid as a formula for the brain to try. YES at (2,0,0) and NO at (0.5,0,0); ON at (0,1,0), OFF at (0,−1,0).
- Tug of war: writing a relationship (a, type, b, s) moves b to (b + f(a)·s)/(1+s); simpler than re-averaging all of b's lines, and it moves at once (D2).
- Grid cell = 0.02 (a told value, CELL).
- Heartbeat: BEAT 1000 ms resting, BUDGET 3000 steps per beat, back-to-back beats while any run can step; the loop also wakes on input.
- Runs past PARK (400) live runs park onto the sixth's PARKED list as memories (not dropped).
- The sixth's lists are memories of kinds GAP, IMBALANCE, TEST-GUESS, QUESTION, SLOW, PARKED (one per subject and kind); FIND KIND gives the oldest due one, and an item tried n times waits PATIENCE·2ⁿ seconds before it is due again, so an idle brain doesn't re-chew the same item every second.
- After a restart the brain resumes from brain.db and writes a RESUMED memory on the timeline (the gap shows between it and the last beat).
- Dev brains: builders try lay files on throwaway pre-birth brains under the scratchpad (`devup.sh`); only the lead births and lays into the real brain at /home/neuron.
- The brain runs as a systemd service (`neuron.service`, user neuron): ProtectSystem=strict, ProtectHome=read-only, writes only to /home/neuron, MemoryMax 4G, CPUQuota 150% (it shares hp2 with the builder during the turn). Restart=on-failure and enabled at boot, so a crash or power loss resumes from brain.db (§12.3; the owner allowed restarting from where it stopped).
- During the told window a kernel fix means reinstalling /usr/local/bin/neuron and restarting the service; the brain resumes from brain.db with a RESUMED memory. After told ends, nothing is reinstalled.
- (primes) A prime acts on what is in hand (the pad) and waits (pushes itself) when it isn't there yet; a test's verdict is handed on as YES or NO. 45 primes have actions; 20 are laid as gaps for the brain to fill (people, body, all, much, little, feel, see, happen, be-somewhere, live, die, long-time, short-time, some-time, moment, above, below, far, side, inside).

- (questions) A newborn word is asked about down the ladder: recent memory (an unnamed gate the last act left), what it arrived related to, a source, history, then a labeled guess, then asking back. Words born while reading a source only get their usual question, so reading doesn't cascade.
