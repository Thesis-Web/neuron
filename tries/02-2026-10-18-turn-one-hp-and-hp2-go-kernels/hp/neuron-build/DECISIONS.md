# DECISIONS (turn one, built on hp, 2026-10-18)

One line per decision the documents leave open. Settled items from NOW and the blueprint are not repeated here.

- Machine is hp (this box, hostname jameshp), not hp2. The brain is user `neuron` (no sudo, no keys); the kernel binary lives at /usr/local/bin/neuron (root-owned), lay files are copied to /opt/neuron/lay (root-owned, readable) on load.
- Go SQLite driver: modernc.org/sqlite (pure Go, no cgo). The only dependency.
- brain.db uses the rollback journal (not WAL) so the adversary can read it with `sqlite3 -readonly` from another user without write access to the folder.
- The physics words take their addressing mode in the binding (READ.rel, FIND.label, WRITE.shard, ...). The modes are the row kinds the blueprint already names; no new words.
- Pad words DUP, DROP, SWAP, OVER are physics (the run's own scratch pad moves). They cannot be built from the other words.
- READ.next (quote): takes the head of the remainder as data instead of hopping to it. Written `'name` in lay notation.
- WRITE.rest: puts a gate or list at the front of the remainder ("run this"). GO only resumes (sets at/from) and is how the miss process returns.
- A plain gate (no binding) pushes itself onto the pad when passed: passing a meaning puts it in hand. THIS = the pad top.
- A relationship-type gate is bound to two formula strings (forward, back). Passing it with a gate on the pad reaches along it: stored line first, then formula + FIND.point (blueprint §5.3 steps 1-2). The reach is physics; the formulas are neuron code the brain can rewrite.
- Placement (tug of war, §5.5) runs as physics inside WRITE.rel: both endpoints are re-placed from all their relationships by the type formulas at once. Points of neighbours move when they are next touched by WRITE.rel.
- Triggers live at gate level (arrival -1, head -1 = the gate's usual triggers) plus optional per-shard rows. The step fires both. A new shard therefore "copies" the usual triggers by reference, not by duplicating rows.
- Told process strings are laid with their inner shards (gate_i, gate_i-1, gate_i+1) and one default-arrival shard (P, -1, g1) for the first hop. -1 means "the gate's usual way"; a specific arrival overrides it. This is what keeps the miss process itself from missing.
- Branch shards: a test's outcome goes at the head of the remainder; the shard (test gate, arrival within the process, outcome) -> branch process. Builders wrap tests in their own process gates so the arrival is unique.
- Run signature = the input's gate sequence (the words), not the full trail. Shape = the coarse direction code of the path through those gates' points (sign per axis per hop). Same shape string = similar shape.
- A memory row id is reserved when a run starts (or reused if a row with the same signature exists), so every row the run makes carries `by` = that memory. The lay loader writes a `told` memory per file; told rows point to it.
- Run ids are handles within one life and restart at 1 each start; memory ids are the durable pointers.
- Every row has made (told|sourced|derived|spawned|guessed|core) and by (memory id). Receipts are those `by` pointers plus the receipt table.
- Case is folded in the encoder (shift is a key modifier, not a meaning). Labels are stored lowercase. No other text work.
- One label per (text, language) -> one gate. A second meaning of the same word hangs off that gate by relationships. Default language is `en`.
- SAY says a gate by its label; a gate with no label is said as #<number> (its address is its name at root). A text item is said as-is (it is the speaker's own word, never the kernel's).
- Runs that exceed the told step limit, or starve below the worth floor for the told number of beats, are parked as rows (kind=parked), one row per (gate, subject) so repeats do not bloat. The sixth picks them up.
- A run that ENDs itself writes nothing. Only a run whose remainder empties goes to the end-of-run process, which writes the memory. So the sixth on empty lists writes nothing (idle beats write nothing).
- The brain's CALL runs programs without a shell, as the neuron user, from the source gate's `how` plus the pad arguments. The shell itself is a source (`sh -c`) so the brain can write and run its own programs; staying home is the core-value check, not a kernel rule.
- The talk port is a unix socket /home/neuron/ports/talk; lay files and told-ends go over /home/neuron/ports/lay (group neuron only).
- The kernel is started by hand (`sudo -u neuron neuron run`); no systemd auto-restart, because killing it ends it. Power loss: start it again and it resumes from brain.db with the gap on the timeline.
- Core-value rows: memories of kind `core` and gates laid in `core` blocks (made=core). The kernel refuses every WRITE, DELETE and MOVE that touches them.
- A question run starts at its trigger's process gate (not at the subject gate), carries the subject on its pad, and inherits the shape of the run that asked it; read-steps in a question run reads the root run's steps. So questions are about the run that asked them and never re-fire the subject's triggers.
- Landings queue on the parent and reach its pad only when it waits or its remainder empties, so a landing never breaks a process mid-flight.
- The sixth's list kinds (gap, imbalance, guesses, questions, slow) are bound names (kind.*), so rows print their kind as a word.
- rot (a b c -- b c a) is a pad physics word like dup/swap/over; read-input gives a memory's own input gates and shape; NEURON_TRACE=1 logs every step (a dev aid, off in the live brain).
- Only a root run's memory carries a shape in the shape index; a question run's memory has none (its shape is borrowed), so find-shape returns runs, not questions about runs.
- B (20-memory): the miss spawns a new word's gate at the arrival gate's point (the related gate in hand), not the origin.
- B (20-memory): an outcome gate is told from an ordinary gate by geometry, with no literal: its distance to found plus its distance to no equals the span found..no, read from the roots' own points.
- B (20-memory): the "I don't know what to do here" questions row is keyed by the gate that lacked the branch (one row per gate); its outcome and body are the outcome that arrived.
- B (20-memory): the miss fires ask-what-is as a question run (split), not inline, so the miss's pad is the same whatever ask-what-is leaves.
