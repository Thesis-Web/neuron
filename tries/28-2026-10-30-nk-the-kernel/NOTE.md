## What was built

**The kernel (`kernel/nk.h`, `nk.c`, 2 files, C).** A brain is a region in memory: its encoder (symbol to gate, gate to symbol), its neurons (one region per gate, a list of shards keyed by (before, trigger) in a hash, found by the gate number as an index: the telephone number), its runs (arrival, parent, root, kind, cell, about, clock, the seq of gates, the data sheet, the indices of its receipts), one receipt array per brain in the order of the hops, its memories (one per ended run, the newest with a given line found by hash), its timeline, its mailboxes (input, third, secondary, out_user, refused), the hits that carried a call or spawn, and the hop stack. The eleven triggers of egg6 are transcribed as C functions, one each: a line arrives (cut into symbols by egg6's rule, new symbols born into the encoder, the first landing pushed), a return arrives (the reply run under the run that asked), a replay (a new run from said with the source's seq), the landing (v6's key: the nearest symbols that are not the space; the shard found or laid, its times bumped), the hit (the receipt; ended, the next landing, the newgate cell and the born landing via 1, the spawn, the call, the BUILD marks and the span to mother, in hit_go's order), the end (the memory, the timeline, `seen : N` to the sixth by a nested call, the parent's cell, the node row, complete). No SQL inside a hop. Two brains in one process; main tells the sixth and the sixth types into main by calling each other's line_in.

**The bridge (`nkvt.c`).** Mother is one in-memory SQLite connection. Its tables are the brains' regions, seen through one virtual-table module: `label`, `neuron`, `dna`, `node`, `run`, `seq`, `run_sheet`, `run_receipt`, `run_memory`, `timeline`, `input`, `third`, `secondary`, `out_user`, `refused`, `hit`, `land`, `hop`, `clock`, `shards`, `complete`, `replay`, under `main` and `sixth`. `dna` is one name in SQL and a region per neuron underneath, keyed (gate, before, trigger) or by gate; `run` by id, parent or about; `seq` and `run_sheet` by run or (run, cell); `run_memory` by run, gate or input; `hit` by (gate, call IS NOT NULL); `run_receipt` by run or id range; `label` by gate or symbol. A write into them is the physics: an insert into `input` is a line arriving, into `secondary` a return, into `replay` a replay, into `run_sheet` a cell, into `dna` a shard, into `neuron` a birth. The tables the lines create themselves (`rel`, the sixth's `asked` and `spawned`) are real tables in the same connection. The sources are attached as before and their triggers call `mother()` as before. Every read is counted as keyed or scanned (`scans`), every text pasted is timed (`profile`).

**Mother, the egg, the socket (`nkio.c`).** Mother's paste is tries/19's mother.c in spirit: a prepared-statement cache, rows joined with " | ", `ok`, or `error: ...`. The egg is egg6's 80 symbols in their order (`egg-symbols.txt`) plus the six words of the kernel's born line, INSERT INTO neuron gate VALUES dna, so that line can run before anything is born, as v6's egg hand-lays the words of its own CREATE TABLE line; every hand-laid symbol has a region; row 0 shards on the arrivals, born and the sources; shards = 15. The born line is `BUILD INSERT INTO neuron ( gate ) VALUES ( newgate ) ; BUILD`: a birth is a row, not a table. A socket on 127.0.0.1:7007 takes one request a line: `type main|sixth <text>` (runs until that line's run has ended and the stacks are empty, answers the sheet as the bottom did), `q <SELECT>`, `graph main|sixth` (the page's bundle), `export <dir>` (every region as plain tables in brain.db and sixth.db), `stats`, `profile`, `scans`, `pump N`. A journal (`NK_JOURNAL`) appends every typed line so a fresh kernel can be given them again in order.

**The lines (`kernel/LINES-nk.txt`, `FIRST-RUNS-nk.txt`).** LINES-v6 with 27 of 60 changed by one rule and nothing else: a gate's table is a dna row (`UPDATE "X" SET ... WHERE` becomes `UPDATE dna SET ... WHERE gate = X AND`; `FROM "what"` becomes `FROM dna WHERE gate = what`; `FROM "what.node" n` becomes `FROM node n WHERE n.gate = what`; the create tool asks `neuron` instead of `sqlite_master`), and the two born lines. The other 33 are byte for byte v6's. The first-runs file has one such line.

**The door (`door/serve8.py`, the page).** The v6 page byte for byte in its look and its drawing; two reads changed (a neuron's node rows by gate; the brain count tile reads `neuron` instead of `sqlite_master`), the title says nk. Every request becomes one line to the socket; the door decides nothing. On hp it runs bound to the LAN: http://10.31.1.106:8058/ from the hub, or `ssh -L 8058:127.0.0.1:8058 james@10.31.1.106` and http://localhost:8058/. `kernel/run-on-hp.sh fresh|resume|stop` builds, lays the sources from their egg (`sources-egg`), starts the kernel, types the sixty lines, starts the door; resume types the journal again after them.

The sixth: the same, 2 lines of 5 with the same text, both identical. The whole-brain shards: 614 identical of about 660 by symbol, the rest the words of the changed lines. Judged by the test, not by me: the test is in the folder and runs against any export.

## What is not there, said plainly

Step back: not laid (the receipts are the full trace; an inverse per hop is not). Threads: both brains run in one loop, a batch of each in turn; a thread per brain and the hc and the guesser as brains of their own are not there. The kernel reproduces v6's physics; it does not change them: the owner's open items (the hc's again, the nap, the hop lines of tries/27, the underscore) are lines for the owner, not kernel work.
