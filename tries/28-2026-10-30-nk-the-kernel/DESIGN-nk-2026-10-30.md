**The owner's words, the ground.** "The hop is simple and cheap basically just the spacebar in a sentence." "Each neuron table is just a meaning as a 3d point that has a symbol that represents it, the space between those symbols is a hop, jump, call, spawn." "Hops and dna reads should be lightning fast... focus on pattern matching the graph instead of searching a corpus... calling a telephone number or a point number." "Any full table lookup is waste, ridiculous, will never scale... the design is designed to carry 5 million neurons with billions of dna rows, and trillions of relationships." "A neuron cannot be a single table with rows... a miss is much more costly, because you don't miss, you land on something else." "On its own kernel the kernel is talking to the silicon not sql, so probably no need for sql... purpose built to serve neuron and only neuron and anything neuron wants to add to it, it builds itself later." "Recursive, step forward, step back, allow for back population and back propagation, allow for multiple dbs to run next to each other and communicate fast each way, allow for output to get to the browser." "Using 7.? the newest brain as a blueprint." 10-15: the seed is now, new, lay, write, again, end, forget, and the hop; everything else is a formula, a run of those, taught once, hit by name. 10-23 §12: the graph is the code; no engine, walker or helper outside the brain does its thinking; mother is a router and a traverser.

**Two rules the kernel is built under, and the test of each.**
1. *No choice points.* The kernel performs the physics a row asks for and nothing a row did not ask for: no order it chooses, no match it ranks, no retry it invents. Test: every behavior the brain shows is traceable to a row (a DNA row's call or spawn, a cell, a line in a mailbox); if a wanted behavior needs the kernel edited, the kernel was deciding, and that is the failure of hp, hp2 and v3 again.
2. *No scans.* Every find is by key: symbol to gate (hash), gate to its neuron (index), (before, trigger) to the shard inside that neuron (hash per neuron), run to its receipts and cells (index), gate to the returns about it (the neuron's node list), (input, source) to the memory of a truth (hash). A formula that asks for a whole table gets it, as a deliberate read, never as the way to find one row. Test: the cost of a hop, a birth and a cell does not change when the brain is a thousand times larger.

**The agreement test, written first.** The blueprint is the live v7 brain's egg (tries/19, 80 hand-laid neurons, the same gates) and its 60 tool lines. The same lines typed into the kernel must lay the same shards (gate, before, trigger, call, spawn, times) in every neuron and write the same cells on the same sheets, and the receipts of the user's lines must list the same gates in the same order. Judged by diff of the kernel's export against the blueprint, never by a ledger. Where the kernel's egg differs on purpose (a birth is a row, so the born line's text is the kernel's), the difference is listed, not hidden.

**What the kernel is.** One process, C, talking to memory. A brain is a region: its encoder (symbol <-> gate), its neurons (gate -> a region holding that neuron's shards in a hash keyed by (before, trigger), each shard id, call, spawn, times; and the neuron's node list, the returns about it), its runs (id, arrival, parent, root, kind, cell, about, at, moment; the seq of gates; the sheet of cells; the receipts), its memories (one per ended run today, keyed by content for `again` when the owner says), its timeline, its relationships (hash by gate, kind, other), its mailboxes (input, third, secondary, out), its hop queue (in memory, newest first, as hit_go's order assumes: a call or a birth finishes before the landing after it). The physics are the v7 triggers, done natively: a line arrives, is cut into gates (new symbols get gates), becomes a run with its seq and its first landing; a landing finds or lays the shard, bumps times, writes the receipt, and from the shard's call or spawn starts a replay, from the next symbol's table-or-not goes on or births first, from a closing BUILD mark hands the span to mother; a run that ends writes its memory and timeline, fills its parent's cell, adds the node row, tells the sixth. Several brains are several regions; a line from one to another is a row in the other's mailbox; the kernel runs them in turn today and as threads on their own cores when the regions are locked per brain (the next step, not this one).

**Mother and SQL.** The kernel has no SQL inside it. The brain's formulas today are SQL text in BUILD spans, taught by the owner, and the kernel does not take them away: mother pastes a span into a SQLite connection whose tables are the kernel's regions seen through a virtual table module (no copy, no catalogue of neurons: `dna` is one name in SQL and per-neuron regions underneath, found by gate, never scanned), with the sources attached as the SQLite files they are. When the brain re-teaches its formulas as runs of primitives, the connection is no longer needed. That is the owner's path ("it builds itself later"), not the kernel's.

**Durability.** An append-only log of what the kernel was told and laid (lines, shards, receipts, cells), and snapshots of the regions: sleep is a snapshot, a memory is a replay, as the owner said of the receipt. Export to a SQLite file for the diff and for reading.

**The door.** The kernel listens on a socket: type a line, read rows, read the graph. A small door in Python serves the same page as v6 over it (the owner: "I really like the look of the one we have").

**Drawbacks, said before building.** Everything SQLite gave free is the kernel's to build: recovery, reading, the page's reads. The formulas keep SQL until re-taught. The builder is the same one whose three kernels held the choices; the two rules and the diff are the guard, and the owner's reading of the rows is the court.
