## The chain, in the brain's rows

A define run ends with its `unknown` cell (152) filled with the gates of its definition's symbols that no source return is about. To the sixth that cell is complete (state 1), so until tonight the sixth asked why only for empty cells. Now: every line that ends tells the sixth `seen : N` (memory_go, for the user's lines and the sixth's own alike); the sixth's observing line, laid again, also reads every define run's `unknown` list, splits it (json_each), and writes into its table `spawned` every gate that no define run has asked about yet (no run beginning with define, 153, has `what` = that gate). A line of the owner's, `define unknown : N`, fires a formula on define's (heard, unknown) shard that marks the N most-shared pending unknowns (the count of unknown lists that hold the gate), sends each as a line `define : X` into main's third mailbox, from the sixth, and says how many. A define line from the sixth lands on define's (the sixth, :) shard, bound to the define run 10516, so it defines exactly as the owner's lines do; when it ends, the sixth collects its unknowns in turn. The compounding is the brain's; the amount per line is the owner's word.

**The cost, said plainly.** A define costs 25 to 80 s with the sources as they are (about 40 s on average). The first frontier is about 4,700 words; each define adds new unknowns and the frontier closes only as the sources' defining vocabulary is exhausted, which is likely 15,000 to 30,000 words: a week or two of the brain running without pause. The brain as it runs today does one typed line as one mother call, one SQLite transaction and one door job: a cascade that sends every unknown by itself would hold the prompt and the page for that whole stretch, and a crash or a stop would roll the whole of it back. That is why the live lines are the paced form: the brain collects by itself on every line, and defines as many as the owner's line says (`define unknown : 100` is about an hour; `define unknown : 500` is a night). The self-feeding form is one line, the observing line with the send inside it (at the end of `UNKNOWN-LINES`): the owner's to type when wanted, with the above in view.

## Undo, at the prompt

`change call : define from 11254 to 0`? No: the (heard, unknown) shard would then fire nothing, which is the undo; the tool writes the column where it equals the old value, so: `change call : define from 11254 to 0` leaves a 0 call (fires nothing). At 6>: `BUILD UPDATE sixth."82" SET call = 1019 WHERE before = 6 AND trigger = 68 ; BUILD` puts the observing line back to the one without collection. The (the sixth, :) bind on define can stay or go: `BUILD UPDATE "153" SET call = NULL WHERE before = 5 AND trigger = 68 ; BUILD`.
