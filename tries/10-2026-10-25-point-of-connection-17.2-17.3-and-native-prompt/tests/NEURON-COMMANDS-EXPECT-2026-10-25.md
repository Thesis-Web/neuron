## How a command is presented (the owner's key design, made with what the brain can already be taught)
Each command is a formula under its own word ("learn:", "define:", ...), bound to the DNA row its key lands on when the line
starts with it: "learn : -> learn:" lays the row in learn for (arrival heard, remainder ":") with trigger learn:. So "learn : store"
fires learn:, and the word learn inside a definition, or anywhere else, fires nothing. Three-word keys: "find meaning : -> meaning:"
(the row in meaning, arriving from find), "print run : -> print:" (the row in run, arriving from print). "run backpop -> backpop:".

## What each command does (MY READING of the owner's names; each is a taught line he can retype)
- learn : x   source x if it holds no definition yet (the told sourcing: every source asked; each answer comes back as a run
              "return from <the line> from <source> /build <definition>"; its end writes x's definition memory and a cell in the
              asking run's data sheet); then say how many definition memories x has.
- define : x  say x's first definition, read from its own definition memory (the words after /build), not from a text table.
- run : x     run the words after ":" as a line of their own (a sub-input of this run). It goes through decide, so a line already
              remembered is answered from memory.
- test : x    run the words after ":" again the long way (never from memory), then compare what they say with what the brain
              remembered saying for that line: balanced (the same), shift (different), or no memory. (Progression and digression
              need an expected output; not built.)
- build : x   run x's definitions that came back but were never run as returns (the told LIMIT 8 skips the rest), as return runs;
              then say how many definition memories x has.
- find meaning : x   say what the brain holds as x's meaning: its live place, its number of definition memories, its formula.
- print run : say the previous line's path (its gates, as words) and its data sheet (its cells).
- run backpop the place process applied to every word that holds measured rows and has no live place yet; then say how many
              live places there are. (Back population: a process applied to the rest of the corpus it fits.)
- place : x   17.1's place, keyed the same way.
