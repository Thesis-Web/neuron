Point Of Connection v6

The live v6 brains behind a local door, serve6.py: main, the sixth, the guessing brain and eight source brains, all SQLite, all triggers; mother pastes what the brain writes. The door types a line into the prompt you choose and runs the SELECTs this page asks for; it decides nothing. The stage is 17.3's: every point a gate of the encoder, every line a row the brain holds, each a spring with the kind's pull; heard, the arrival gate, is the one fixed point; a run is walked hop by hop from its receipt. Positions are this page's drawing, not the brain's. The rails are tabs.

Kinds of line: on, off, pull, direction

Every line is a row the brain holds. A DNA row (shard | before | trigger | call | spawn | times) in a neuron's table gives up to four: the symbol before to this one, this one to the symbol the run goes on to, and a call or spawn to the first gate of the run it replays; made-of ties a symbol that calls a run to every gate that run passes. A definition row ties a symbol to the words of the lines its sources returned; answered ties a source brain to the symbols it answered. A memory node (small, green) is a run_memory row: it sits on the shard that ended the run and is tied to the words of its line. The rest are relationship rows (rel) by their kind word, and your map. Each line is a spring: the kind's pull (its slider), times how much of that kind the brain holds; a row laid again pulls harder (17.3's pull law). A direction makes a line of that kind push its second word that way from its first, or across origin. Nothing pushes points apart except the space above; heard alone is fixed.

How to read the stage

  • The light point at the center is heard, gate 1, the arrival gate every typed line comes from: the one fixed point. Everything else is where its lines pull it.
  • Grey points are the 80 hand-laid neurons (the arrivals, the sources' gates, the cell names, the symbols of the born line). Blue-grey points were born by the born run. Orange symbols carry a call or spawn (a formula bound to a shard). A point that holds definition rows is lighter. Teal, large: the source brains. Small green: memory nodes. Dim: words of your map the brain has no gate for.
  • A run is drawn through the gates of its receipt, in order; the hop being stepped glows, and a flash goes from it to the gate the run goes on to and, in orange, to the first gate of the run its shard calls or spawns.
  • The stage is the brains now. Every read is a SELECT through the door; nothing is replayed from a log. Stepping walks one run's receipt as the brain wrote it, and play goes on into the next run of the same line.

What is read, from where

  • Points: main.label. Lines: every DNA table ("k"), the rel table, the call and spawn columns, the definition nodes ("k.node") with the return runs behind them, run_memory, and the map source's corpus.
  • Step: run_receipt. Run: run_sheet (the cells), the child runs (returns, calls, spawns), run_memory, timeline, out_user.
  • Selected: the DNA table of the gate, its definition node, the rel rows, the memory rows on its shards, the run that bore it.
  • Brains: sqlite_master counts of main and the sixth, the sixth's inputs, guess.guesses, the refused tables.

What is this page's own, not the brain's

  • x, y, z. The brain holds no positions. The springs, the rest lengths, the space between points, the step limit and the colours are the drawing's; they say nothing measured.
  • The door's calls: type a line, read the graph, run a SELECT, list the lines files, lay the eggs again. The tabs.
  • The two lists under Type are files beside the brain (LINES-v6.txt, FIRST-RUNS-v6): clicking a line only puts it in the prompt; you press run. Nothing types a file of lines by itself.
