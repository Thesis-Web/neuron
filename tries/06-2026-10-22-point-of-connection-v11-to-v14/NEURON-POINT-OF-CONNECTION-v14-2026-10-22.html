Relationship kinds: on, off, pull

The pull is your law: a point moves by the ratio of the lines pulling it each way, times each line's trust, times how defined its kind is. Strong kinds (synonym, antonym, class) pull harder than loose ones (topic, context, method, use, before, after), and a kind pulls harder as the brain holds more of it. The slider is the situation. Counts: lines the brain wrote, plus dim lines from your map.

Your map's readout, carried over: a R1 b, b R2 c. Back means c was a again. The kind that already joins a to c most often is the formula the graph suggests.

Sources, as the brain has found them

Every reply is checked. Kept: rows about the word that was asked. Set aside: rows about other words. Empty: nothing came back. This record is what a brain could use to choose where to ask; today the choice is the source formula you type.

What 14 changes, from your words

  • "the mother does no work other than the traverse." mother is now real SQLite plus one routine that carries text out and replies back. Nothing else in the page decides for the brain.
  • "the JavaScript still decides to ask every source... that is wrong." A fresh brain asks no source. born fires the word source; source asks only where its formula says. Teach it, or use the first preset.
  • The primitive runs are gone. No find, read, compare, join or write in code. A formula holds the SQL itself, so what leaves through output to sources is exactly the row the brain holds, holes filled.
  • "each other brain has a mailbox... the mother listens... when it's populated." Each source is its own database. An ask lands in its inbox; its own trigger does the work at once and says its outbox is populated; mother picks it up, empties the outbox, and brings it back through secondary input, into the cell the run opened. A source that never signals leaves the cell waiting. Nothing runs on a timer.
  • "what says? is this the data I asked for... the data I needed, did I ask wrong?" Every return is checked with those three questions, and the answers are in the context table and the log.
  • "2. must be fixed correctly." A line answered from memory now counts in a word's meaning: the words point at that memory, so the record is the run that made the memory plus the recall.
  • "the sql words are hand laid... need a sql doc look up." The SQL words are hand laid, around the actions. Their source is the SQLite docs, as a source brain of their own.
  • Formulas are rows. The brain's formula table holds them. Teaching a word again ends its old row and adds a new one: a truth shift, nothing erased. derive, if you type it, writes a formula row itself, marked derived, a guess.
  • A failed ask steps back. When a formula's ask comes back empty, the run steps back to the neuron that fired it and takes another of its rows whose trigger names a different formula, if it has one. If not, the gap says so.
  • Layout and rails, as you asked: your side left, mother and the sources right, the graph's line controls in their own rail, and nothing jumps when you touch them.

AS: what it does, measured

You asked whether AS is a syntax mark like ( or ; or whether it means something. Measured tonight in real SQLite, version 3.39.3, the same engine this page runs:

statementwith ASwithout AS
CAST('7' AS INTEGER) + 18syntax error
CREATE TABLE t2 AS SELECT ...a table made from the rowssyntax error
WITH q AS (SELECT ...) ...the query gets the name qsyntax error
SELECT value AS who FROM statecolumn named whocolumn named who, same row
  • In three places AS does work the line cannot do without. The thing on one side takes the type, the rows or the name on the other. Take AS away and SQLite refuses the line.
  • In the fourth, the machine does not need it, because SQLite reads the name by its position. The person reading the line does: AS says, out loud, this is the name. Your efficiency point holds, and the energy saved is the reader's.
  • The SQLite docs say what it does, in three sentences, now in the docs source brain. Last version said AS appeared only in the syntax. That was my extraction failing, not the docs. Corrected.
  • English "as" was fetched tonight from all five sources. The rows that are really about "as" say: to the same degree; denoting equality or likeness; like; at or during the time that; for the reason that. Whether SQL's AS and English "as" share a root meaning, one thing standing as another, is a hypothesis. It is not laid. It is the next test.

The router: is it too slow?

Measured tonight on this machine, with SQLite through Python, a satellite with a corpus, an inbox, an outbox and its own trigger:

how the satellite is reachedper ask, out and back
attached to the same process0.011 ms
its own process, connection kept open0.22 ms
a new process started for every ask69 ms
  • A brain cannot reach another database by itself. SQLite refuses it: "qualified table names are not allowed on INSERT, UPDATE, and DELETE statements within triggers." I predicted a temporary trigger could do it; it cannot either. mother is the only way out, which is what you said she is.
  • The satellite's own trigger fires the moment the ask lands. That is populated-driven, with no timer anywhere.
  • The mailbox must be emptied on pickup. My first run never emptied it, and each pickup scanned every old reply until the run stalled. Measured, then fixed.
  • My thought: keep the mailbox and the router. They are not slow. What is slow is starting something per ask: a new process, or an ssh session per ask. Keep each source brain resident, its database open, with its own small mother that sends when its outbox fills. On hp and hp2, keep one connection open per source and put many asks through it. Network time adds to the 0.22 ms; I did not measure it, because those machines are yours.
  • Daemons, queues, LISTEN and NOTIFY are this same idea in someone else's code. A mailbox made of the brains' own tables keeps it inside the rows, where the brain can see it.

The check on every return

  • Is this the data I asked for? Each source row carries the headword it is about. Asked for "as", Webster 1913 sent "So" first, and three entries for "As": the ace, arsenic, a Roman weight. Merriam-Webster sent altostratus, arsenic, the abbreviation AS, and the prefix "as-". The thesaurus sent "as far as", "as for", "as if". All set aside, each with its reason. Only rows about "as" are kept.
  • Is it the data I needed? At the return, needed means it fills the cell. When the run ends, sense asks again against the expected output; if the run came out wrong, every return it used is marked: maybe not what was needed.
  • Did I ask wrong? An empty reply asks it, opens a gap, and the run steps back to the neuron that fired and takes another row, if there is one. A source that never answers leaves the cell waiting, and the run knows it is waiting.
  • Not solved: which sense of a word fits this sentence. WordNet files arsenic under "as"; its own synonym list spells it As, and the stand-in reports that, so it is set aside. A real source brain would have to make that call itself. Choosing the sense that fits the run is part of the meaning problem.

Source brains, the other brains, and the sixth

Your design, as you put it: the main brain is cognition, reasoning, problem solving, state, history and time. The source brains understand the ask and answer from their corpus. Other brains test, guess, form hypotheses, dream and observe. The sixth watches, sparks questions, holds the morals, ethics and checksums, and drives growth.

  • It makes sense, and tonight's facts back it. A brain cannot reach another database by itself, so every brain needs a traverse like mother. A mailbox is the cleanest edge between two brains. The "as" replies show why a source brain needs its own reasoning: dictionaries answer with neighbours, and someone has to understand the ask.
  • The guessing brain is where a language model fits, if it fits anywhere: it supplies candidates, and the main brain tests them against sources and memory. The guesses never enter as truth.
  • The sixth as a separate brain fits a hard fact: a brain cannot fully check itself with the same rows that made the mistake. Two cautions from your own rules. It should reach the main brain only through mother and mailboxes, so every change it makes is a row the brain can see and walk back. And when it writes SQL into the main brain, that SQL is told, not learned. The line between correcting the brain and doing its thinking for it is where the old builds went wrong.
  • "Why did I think that that way?" That question is the receipt walked back. The sixth asking it of the guessing brain is the same mechanism the main brain uses on itself, one level up.
  • Not built here. This page has the main brain and seven stand-in source brains. The guessing brain and the sixth are not on it.

The meaning problem, where it stands

  • Root code: the hand-laid SQL words and the physics. What each does is measured from mother, not told. Click an SQL word to see what it has done so far.
  • Shorthand: a word's formula, a row. Its card shows what it compiles to: the exact statements it sends out and the physics it fires, level by level.
  • Modifiers: the other words in the line fill the holes and choose which row of a neuron fires. Measured per line.
  • The compiler's output: the difference a word makes when the line runs with and without it. That covers the silicon, the graph, memory and state, the questions fired, the sources asked, the columns returned, and the recall.
  • Open: going from a definition to a formula. Two experiments are now possible in this page. AS against "as": does a measured root action match what the sources say an English word does? derive: the brain copies a formula from a word it is like, marked a guess, and the expected outputs score it. Neither is a meaning the brain has found and understood yet.

Hand laid, exactly

  • 14 physical actions, the silicon: READ, WRITE, COMPARE, ADD, SUBTRACT, MOVE, FIND, SPLIT, JOIN, CLOCK, HEAR, SAY, CALL, SPAWN.
  • 16 physics tables with their triggers: input, encoder, decide, lay, born, source, agree, end, sense, memory, timeline, say, BUILD, formula, var, state.
  • The SQL words, keywords and marks: the roots of this build, hand laid as you said. Their source is the SQLite docs.
  • mother: real SQLite and one routine that carries text out and back. She decides nothing.
  • The ports: primary input, output to use, output to sources, secondary input. These are where mother picks up and drops off.
  • Seven stand-in source brains: WordNet, Webster 1913, Merriam-Webster and its thesaurus, Moby, your relation map, and the SQLite docs. Each is a slice fetched on 2026-10-22, behind a mailbox. The real ones would live on hp and hp2 and fetch for themselves; a page cannot.

Everything else is born by typing: every word, row, hop, relation, formula and memory.

Every way I would cheat this build

Kept from 13.1, with tonight's added. The first move toward any of these is the end of the build.

  • Outside the brain. A walker in Python. A central hop function. A position table. A kernel "for speed" that does the choosing. A scheduler. Until 13.1, primitive runs as JavaScript; in 13.1, SQL templates in JavaScript wearing the name of the brain's statements.
  • Deciding for the brain. Asking every source because the code says so (13.1). Writing your map's relations into the brain from code instead of from a word's run (13.1). Both gone.
  • Canned. Template strings, fixed replies, a side table that makes the right answer come out, a meaning as a function, worksheet guesses laid as roots.
  • Shortcuts that lose the long way. A memory with gaps that hides them. My v14 rewrite dropped the rule that reopens it; a test caught it and it is back.
  • Guessing dressed as knowing. Laying facts from my head. Taking the first sense. Taking a source's reply as the answer to the question asked; tonight's "as" shows how often it is not.
  • Calling it done. Tests written to pass. A test that contradicted my own measurement (T10, caught before it ran, logged). A reply that never came treated as a reply (caught by a control). A mailbox never emptied (caught when the run stalled).
  • Drift. Re-deciding what is settled, inventing without saying so, cutting the core to finish. Still JavaScript here: the sixteen physics tables play their triggers in code. In the brain they are SQLite triggers. That is this model's floor, and it is labeled.
