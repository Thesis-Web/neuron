## Your check, on the data sheet living in the memory row

Your words today: the main run finishes in nanoseconds; each tripped trigger declares the cells its run will fill; each return fills its spot; when no declared cell is empty, the larger formulas run and output to the timeline, the user or mother all come from the same memory table; the timeline needs only the receipt pointer, whenever the sheet is finished.

What SQLite does with that, measured facts only: a row can point to the run, and rows keyed by that run then live there with no copy, so "it just lives there" costs no traverse. A trigger on the sheet that fires when a cell is filled can test whether any declared cell of that run is still empty, and that test is populated-driven: it runs only when a cell is written, never on a timer. It cannot loop the way the end run did, because a formula's own cells are its own sheet, not its parent's, and nothing of it comes back as a run that ends. What would have to go: the end run, the reply runs, the `end` fire. What would have to come: a trigger declaring its cells when tripped, which your words specify and which nothing in build sheet 2 does. Whether the sheet is rows pointed to by the memory row, a table per run, or one cell is the one thing your words leave open (row 12).
