## 2. How a new neuron is created (unknown word arrives)

Path, with code:

1. Typed line -> `input`: host18.py:73 `self.con.execute("INSERT INTO input (line, direction) VALUES (?, ?)", (line, direction))`.
   input_run -> `run` (gen18.py:102-104).
2. run_go births unlabeled head/next tokens, then lands (gen18.py:113, 115):
   `INSERT INTO born (word, run, source) SELECT {HEAD(L)}, NEW.id, NEW.kind = 'line' WHERE {L} <> '' AND NOT EXISTS (SELECT 1 FROM label WHERE word = {HEAD(L)});`
   `SELECT motherp('INSERT INTO land_' || {G(HEAD(L))} || ' (arrival, remainder, run, rest) VALUES (?, ?, ?, ?)', ...)`.
   Mid-line, hop_go births the next word the same way (gen18.py:141-142:
   `INSERT INTO born (word, run, source) SELECT {HEAD('NEW.rest')}, NEW.run, ... WHERE NEW.remainder IS NOT NULL AND NEW.rest <> '' AND NOT EXISTS (SELECT 1 FROM label WHERE word = {HEAD('NEW.rest')})`).
3. born_go fires the born neuron (gen18.py:121): `INSERT INTO fire (run, trig, subject) VALUES (NEW.run, {gate['born']}, NEW.id);`
4. fire_go turns the pointer into a run: it re-reads the receipt of the run that taught `born` and types it as a new input of
   kind 'formula' (gen18.py:127-130):
   `INSERT INTO input (line, direction, parent, kind, word, subject, rest) SELECT (SELECT group_concat(w, '') FROM (SELECT l.word AS w FROM receipt x JOIN label l ON l.gate = x.gate WHERE x.run = f.run ORDER BY x.id)), 'start', NEW.run, 'formula', (SELECT word FROM label WHERE gate = NEW.trig), NEW.subject, NEW.rest FROM formula f WHERE f.gate = NEW.trig AND f.ended = 0;`
5. That formula run hops gate to gate (BUILD, ' ', INSERT, ' ', INTO ...; 1,272 hops), each hop writing a `receipt (run, gate, shard)`
   row (hop_go, gen18.py:136). When the second `BUILD` gate is hit, hop_go writes `build` (gen18.py:137-138, the `% 2 = 0`
   rule); build_go decodes the receipt between the two BUILDs, fills `var <name>` holes from `sheet`, and calls mother
   (gen18.py:168-170): `INSERT INTO sheet (run, name, value) VALUES (NEW.run, 'BUILD', mother({decode}, NEW.run));`
   mother executes the text statement by statement (host18.py:46-49: `for st in self.split(text): ... cur = self.con.execute(st)`).

So: the CREATE text is **assembled from the receipt** (table `receipt`, gate numbers joined to `label` for the words), the
holes are filled by the hand-laid build_go, the closing word is the second **BUILD**, and mother runs it. It is not
templated inside a hand-laid trigger. But the text the receipt replays is the taught born line, which **make_sheet18.py
generated in Python from the same template the hand-laid gates use** (make_sheet18.py:12: `+ gen18.gate_trigger_holes() + " ; "`;
gen18.py:44-45 `GATE_TEMPLATE.format(DNA='var dna', ENTRY='var entry', GATET='var gatet', GATE='var gate')`).

## 3. The hop

One gate trigger per neuron, INSTEAD OF INSERT on the neuron's `land_<k>` view; no per-row triggers, no Python loop.
gen18.py:37-41 (verbatim, holes {DNA} {ENTRY} {GATET} {GATE}):

```
CREATE TRIGGER {GATET} INSTEAD OF INSERT ON {ENTRY} BEGIN
SELECT motherp('INSERT INTO {DNA} (shard, arrival, remainder) SELECT n + 1, ?, ? FROM shards WHERE NOT EXISTS (SELECT 1 FROM {DNA} WHERE arrival IS ? AND remainder IS ?)', NEW.arrival, NEW.remainder, NEW.arrival, NEW.remainder);
SELECT motherp('UPDATE shards SET n = n + 1 WHERE EXISTS (SELECT 1 FROM {DNA} WHERE shard = n + 1)');
SELECT motherp('INSERT INTO hop (run, gate, shard, remainder, rest, trig) SELECT ?, {GATE}, shard, ?, ?, trigger FROM {DNA} WHERE arrival IS ? AND remainder IS ?', NEW.run, NEW.remainder, NEW.rest, NEW.arrival, NEW.remainder);
SELECT motherp('INSERT INTO land_' || NEW.remainder || ' (arrival, remainder, run, rest) VALUES (?, ?, ?, ?)', {GATE}, (SELECT gate FROM label WHERE word = HEAD(NEW.rest)), NEW.run, TAIL(NEW.rest)) WHERE NEW.remainder IS NOT NULL;
END
```
(HEAD/TAIL expand to the `CASE WHEN length(NEW.rest) > length(ltrim(NEW.rest, 'abc...9_')) THEN substr(...) ELSE substr(NEW.rest, 1, 1) END` text seen in gate_1 / gate_293 in the db.)

- Every hop = 4 statements, each handed to **motherp** (host18.py:64-69), not to `mother`. motherp executes the text and
  returns a scalar; it writes no log. The hop is recorded only because statement 3 inserts a `hop` row, hop_go copies it to
  `receipt` (gen18.py:136) and deletes it (:143); `hop` has 0 rows in the db, `receipt` has 1,181,219.
- The hops are nested, not sequential: statement 4 lands on the next gate from inside the current trigger, so a 1,272-hop run is
  1,272 nested trigger frames (hence neuron_prompt18.py:6 `sys.setrecursionlimit(200000); threading.stack_size(1 << 29)`).
- In the db: 1002 gate_ triggers for 1002 neurons; all 1002 normalise to one text (differing only in the gate number).
- Shards: 1002 DNA tables, 4,665 shards, exactly 1..4665, no gaps or repeats, `shards.n = 4665`. One sequence, held by the
  hand-laid counter table `shards` and the `UPDATE shards SET n = n + 1` template.
- bind_go (gen18.py:150-155) also writes DNA rows and trigger columns directly through motherp templates (the `define : ->
  define` line gave g273 row (shard 900, arrival 1 heard, remainder 11 ' ', trigger 273)). The key is (heard, define, ' '):
  the colon is not part of it (bind_go takes HEAD(P) and HEAD(TAIL(P)) only, gen18.py:151).

## 4. Mother (host18.py)

Whole body, host18.py:43-61:
```
    def mother(self, text, run):
        if not text: return 'error: nothing to run'
        reply = 'ok'
        for st in self.split(text):
            self.populated = []
            try:
                cur = self.con.execute(st)
                rows = cur.fetchall() if cur.description else None
            except Exception as e:
                return 'error: ' + str(e)
            picked, self.populated = self.populated, []
            for (s, ask, word, n) in picked:
                out = self.con.execute(f"SELECT text FROM {s}.outbox WHERE ask = ?", (ask,)).fetchall()
                self.con.execute(f"DELETE FROM {s}.outbox WHERE ask = ?", (ask,))
                for (tx,) in out:
                    self.con.execute("INSERT INTO secondary (run, src, value) VALUES (?, ?, ?)", (run, s, tx))
            if rows is not None:
                reply = '\n'.join(' '.join('' if v is None else str(v) for v in r) for r in rows)
        return reply
```
and her second entry, host18.py:64-69:
```
    def motherp(self, text, *values):
        cur = self.con.execute(text, values)
        if cur.description:
            rows = cur.fetchall()
            return rows[0][0] if rows and rows[0] else None
        return cur.lastrowid
```
Beyond executing text and returning rows/errors she:
- splits the text into statements with `sqlite3.complete_statement` (`split`, host18.py:32-40);
- stops at the first error and returns only that error (the rest of the block is not run);
- after each statement reads every populated source outbox, **deletes** it, and **writes rows into the brain table
  `secondary`** (host18.py:55-58) with the asking run's id;
- formats rows into text (`' '.join`, `'\n'.join`, NULL -> '') and returns the constants `'ok'` / `'error: nothing to run'`;
- motherp returns the first column of the first row, else `lastrowid`.
No regex (`re` is imported at host18.py:5 and never used), no silent mode flag, no narration beyond 'ok'/'error: ...'. Neither
mother nor motherp logs the text it ran anywhere in the brain.

## 7. Verdict per criterion

- prompt ---> encoder ---> brain: PARTLY. The line enters a brain table (`input`) as text; hand-laid triggers classify it by
  syntax (' = ', ' -> ') and encode it token by token in SQL (HEAD/TAIL + label) while carrying the untyped rest as text
  (`run.line`, `fire.rest`, landing `rest`). Encoding is inside the brain's triggers, not a stage before it.
- A trigger cannot create; the SQL string is put together by a run and handed to mother: HOLDS for neuron creation (CREATE
